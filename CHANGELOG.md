# Changelog

All notable changes to Maane. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project uses [Semantic Versioning](https://semver.org/). Add each user-visible or operational change under `## [Unreleased]` while making it. The Release workflow turns that section into a dated `## [x.y.z] - YYYY-MM-DD` section and keeps an empty `## [Unreleased]` above it.

## [Unreleased]

### Added

- Sign-in: local accounts with a username, a password, and mandatory two-factor authentication. The first admin is created on a setup screen that stays open for 5 minutes after the server starts, while no user exists. Admins create users and set their role (admin or agent).
- Settings the admin manages, stored encrypted where secret; an environment variable can set and lock a field.
- An audit log of sign-ins, setting changes, and user administration.
- The web UI, in Hebrew (right to left, the default) and English, with light and dark themes, from phone to desktop: the setup screen for the first admin, two-factor setup with a QR code and backup codes, sign-in with an authenticator code or a backup code, and the ticket list. Every user has an Account page (password, signed-in sessions, backup codes, a new authenticator app). Admins have Users (add, change role, set a password, end sessions, disable and enable; the first admin stays protected), Settings (default language, session length; a value the environment sets shows locked with its variable), and the audit log. The default language applies until a browser chooses its own.
- Deployment: one container image for the server and the worker, running as an unprivileged user, and `docker-compose.yml` for a Docker host behind Traefik, with `.env.example` (the image version and the domain) and `docker/env/` (the database password and the keys, which reach each container only from its own owner-only file) as its environment contract.
- Organizations (admins): add, rename, and delete organizations; give each one its support addresses, exact addresses or patterns such as `support-*@example.com`, and its agents; make one exact address the default for mail whose support address cannot be identified; and check which organization gets an address, by the same rules intake uses (an exact address first, then the most specific pattern, then the default). An agent sees only the organizations they belong to; removing them takes effect on their next request, and changing a user's role removes all of their memberships. Every change is in the audit log.
- Settings: the intake mode, listening (the default: Maane only records what it would do) or live. Live needs a default address, and while intake is live the default address can be replaced but not removed.
- File scanning: a ClamAV container (`clamav`, ClamAV 1.5.4, running without root) scans every file before Maane keeps it. Maane trusts a clean result only from a scanner that passed its self-test (the EICAR test file, an encrypted ZIP, and an encrypted PDF), run at start, every hour, and when the address changes. Encrypted files and files beyond a scan limit are marked not fully scanned and never treated as clean; infected files and blocked types are never stored, and blocking one is recorded in the audit log. Files are stored by their SHA-256 under `./data`.
- Settings: Files and scanning, with the scanner's status, a connection test, the scanner address (the bundled `clamav:3310` or your own clamd), what happens while the scanner is unavailable (block, the default, or allow as not scanned), how long one scan may take (150 seconds by default), the largest file (50 MB by default), and the blocked file types (executables and scripts, by extension and by the type read from the content).
- Graph intake: the worker reads the shared intake mailbox through Microsoft Graph, read only (delta queries of Inbox and Junk Email with immutable IDs), stores each message before it moves its cursor, scans the raw message and every attachment and inline image, and keeps only sanitized HTML. Copies, automated mail (RFC 3834 and RFC 3464), the support address (To, then Cc, then the default address), and threading (headers, the body reference code, the `[#n]` subject number, and late originals) decide whether a message opens a ticket, joins one, or opens a linked ticket flagged for review. Tickets get a number and a random reference code. In listening mode Maane opens no ticket and records what it would have done, following each conversation as live mode would. The text, the HTML, and the header values of every message are scanned like files before they are stored, and a flagged field is never stored.
- Settings: Microsoft Graph, with the tenant, the application ID, the client secret (stored encrypted, never shown), the intake mailbox, and a connection test that reads only the mailbox's Inbox folder details. Each can come from a variable in `app.env`, which locks its field; a client secret that reads as an example is refused at start. The deployment notes give the owner's checks against the real tenant.
- Organizations: one that has mail history is kept, and deleting it is refused with a message that says why.
- Tickets: the home page lists the tickets of every organization you can see, newest activity first, with an organization filter and a Needs review filter. A ticket shows its details and its messages in order, each with its sender, recipients, date, and body. The body is shown isolated in a sandboxed frame, Hebrew right to left also when the sender set no direction, with remote images hidden until you choose Show remote images for that message, and links that open in a new tab; a message without HTML shows its text line by line. What a scan blocked shows as blocked with the signature, never its content.
- Files: each attachment shows its scan status in words (clean, blocked with the signature, not fully scanned, waiting for scan, not scanned, unavailable, too large to scan). A clean image, PDF, or text file opens in a preview, decided by its content; PDF pages are drawn by pdf.js without scripts, scanned and faxed pages (JBIG2, CCITT) and JPEG 2000 images included, and a note says that the download has the original. Every stored file downloads, with its name kept safe; SVG, markup, and Office files download only.
- Intake log (admins): every message intake processed, with what Maane did or, while listening, would have done, the support address and organization, the ticket it opened, joined, or would have joined, the reason in words, and the review flags, filtered by mode and by review.
- `zendesk-backup`: saves a Zendesk account (raw records, comments and internal notes, audits, attachments, and inline images) into a local archive, continues from where the last run stopped, and checks the archive without access to Zendesk. See `docs/zendesk-backup.md`.
- Releases: the Release workflow publishes a version from `main` (the image `ghcr.io/shlomiporush/maane` with its version tag and `latest`, an annotated Git tag, and a GitHub Release from this file), after a green CI run of the commit. It never deploys. A run that stopped halfway is finished by the next run.
- Deployment notes in `docs/deployment.md`: Traefik, generating the production secrets once on the server, the setup window, what to back up, a restore test, and upgrades.
- Development: the pnpm workspace, the toolchain container, the repository guards, `scripts/verify.sh` (with the container stack stage), CI, end-to-end tests of the web UI against the container stack, `scripts/local.sh` for a development stack, and `scripts/try-pr.sh` to run a pull request beside it.
